### Drift signals

**Single-host limitation in orchestrator** — the alpha-1 orchestrator dispatches ALL steps to Claude API including Reviewer steps (`reviewer.write-e2e-tests`, `reviewer.review-pr` in `/build`). This violates the cross-model independence constraint that makes Reviewer findings load-bearing (`preferred_hosts: [codex, gemini]` deliberately excludes claude). Today's builds use `--step` to avoid dispatching Reviewer steps, but it's a manual workaround, not a structural defense. **v0.4-beta must ship multi-host dispatch before the orchestrator can be used for the full `/build` workflow.** Risk: if a consumer uses `compass run build` without `--step` today, Claude reviews its own code — the same-model blind-spot problem the framework was designed to close.

**`docs/orchestrator-runs/` is not `docs/`** — artifact write goes to `docs/orchestrator-runs/` to avoid polluting canonical artifact paths. This means after an orchestrator run, the user must manually move/copy the output to `docs/foundation/product.md` etc. For now this is correct (human review before canonical promotion), but it creates friction. v0.4-beta should add git commit automation with an explicit "promote artifact from orchestrator-runs to canonical path" step at the HITL gate.

**9 agents still in `compass/roles/`** — at current pace (1-2 per session), full pack takes 4-5 more sessions. The MVP agent pack per `compass/framework/mvp.md` needs: Designer, UX Writer, Automation (new), Launch Engineer (new), Triage, Observability (new). Of these, none are migrated yet. The orchestrator can already run the Product → Architecture chain; Build chain still requires manual dispatch for Reviewer (by design until multi-host ships).
