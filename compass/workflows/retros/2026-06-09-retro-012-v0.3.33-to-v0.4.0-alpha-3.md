### Analysis

**`[rsc-prop-serialization]` + `[server-action-file-export-purity]`** — both named in `engineer.md` per improvement #52, satisfying the Engineer-side discipline. The gap is the `/build` pre-merge checklist: a Reviewer reading a PR diff has no explicit gate that asks "did the Engineer verify RSC boundary + use-server purity?" Adding both to the `/build` dispatch-graph (#59) closes the loop. Log as improvement #59-adjacent (bundled into the `/build` refactor rather than a separate version bump).

**`[empty-numeric-input-zero-trap]`** — HTML numeric inputs default to 0 when empty; a common bug is treating the empty state as "no input" when the DOM delivers `0`. This is UI-layer: Engineer agent's standard-experience checklist (or a named task in the story's definition of done for numeric fields). Best home: Engineer `implement-story` task → standard-experience checklist item "numeric inputs: validate empty vs zero explicitly." New improvement to log.

**`[cross-artifact-sweep-on-contract-shift]`** — when any contract changes (API shape, data model field, shared type, environment variable name), ALL artifacts that reference that contract need a sweep before the PR merges. 5+ instances across 3 consumer projects (CB-2.2, CB-2.5, CB-3.1, CB-3.2, CB-3.3 twice) = highest maturity signal in this retro. Current gap: nothing in `/build` or Engineer tasks explicitly names "sweep all referencing artifacts when X changes." This is a pre-PR gate, not a code-review-time catch. Priority: promote immediately into `/build` Phase 4 (pre-PR checklist) as part of #59, and add a named gate to `engineer.md` `implement-story` postconditions.
