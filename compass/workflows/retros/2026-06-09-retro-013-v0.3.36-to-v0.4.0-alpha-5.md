## Common patterns

**1. Consumer project is now the primary signal source.**
Every improvement in this batch traces back to the crypto app (CB-3.3). #59 was direct consumer signal (prod defects). #60 promoted those signals into the framework. #61 canonised the sweep discipline those defects named. #62–#63 built the orchestrator infrastructure to serve consumer dispatch. For the first time, no improvement in a 5-entry batch originated from synthetic framework-internal friction — all 5 came from a real consumer using Compass under real conditions.

**2. Fastest codification cycle in framework history.**
`[cross-artifact-sweep-on-contract-shift]` went from consumer signal (#59) → engineer.md enforcement (#60) → canon entry (#61) in 3 consecutive improvements within the same session. Prior fastest was 5 improvements (#005 → #006 for `[hard-line-declaration]`). Enabled by: (a) the pattern had 5+ instances pre-existing in consumer artifacts, (b) the consumer retro captured them cleanly, (c) no intermediate HITL gate between steps. The signal-to-canon pipeline is shortening.

**3. Orchestrator capabilities are compounding fast.**
This batch shipped orchestrator alpha-4 + alpha-5 — two orchestrator versions in one 5-improvement cycle. The cumulative additions: pipeline mode (cross-workflow chaining), `--compass-dir` (consumer decoupling), `--bet` (context auto-load), step logger (structured output), HITL context passing (alpha-3, prior batch). The orchestrator is growing faster than any other framework subsystem.

**4. Live validation as a new quality gate.**
#63 was validated live against the real consumer project — not a synthetic test, not a dry-run. The Architect gate fired correctly on CB-4 (`architecture_required: false` → DRI Decision, no spurious architecture.md), delivery manager applied `[derive-from-state]` discipline correctly. This is the first improvement in framework history validated by actual API dispatch against a production bet.

## Drift signals

**Consumer project on v0.1 framework (structural drift).**
crypto-app has `compass/roles/` (not `agents/`), pre-dispatch-graph workflows, and v1.0 in config.yaml. The `--compass-dir` workaround is working for orchestrator dispatch, but the consumer's Claude Code interactive path (skills, /build, /create-brief) still reads from the embedded old framework. This is a growing divergence. A formal consumer migration guide doesn't exist yet. If the consumer starts a new bet using the old workflow shape, it won't benefit from the agent discipline improvements shipped in #59–#63.

**Orchestrator cannot write files or run shell commands.**
Every orchestrator improvement in this batch produced a text output the user had to save manually ("you save this"). The Engineer's implement-story task is effectively unreachable via orchestrator — it needs filesystem write + git + test execution. This is noted and understood (CLAUDE.md acknowledges it), but the gap is widening as orchestrator capabilities grow around it.

**`agent-handoff.yml` remains unverified placeholder.**
Flagged in Retro #012 (Codex CLI flags unverified). Not fixed this batch. The GitHub Actions path for post-PR Reviewer dispatch is still a placeholder. Low urgency while orchestrator API path is working, but should not drift indefinitely.
